# 输出质量风险档案

预测 `github-deep-search` 在用户可见输出中可能出现的质量问题，以及对应的防护措施。

## 风险 1：API 速率限制导致结果不完整

**风险等级**：中

**表现**：匿名调用时，6 次 API 请求可能只有前 1-3 次成功，后续被限速。导致搜索结果偏少，且可能遗漏 stars 排序或 updated 排序的结果。

**防护**：
- 脚本检测 403 限速响应并优雅降级，用已获取结果继续
- 输出中明确标注 `⚠️ 部分请求触发 API 速率限制`
- token 自动探测链：`--token` 参数 > `GITHUB_TOKEN` 环境变量 > `gh CLI` 登录态，本机已登录 gh CLI 时零配置提速
- 请求间加入礼貌延迟减少触发概率

**残留风险**：无任何 token 时结果覆盖面受限，但不会报错或返回空。

## 风险 2：Trending 页面结构变更导致解析失败

**风险等级**：中

**表现**：GitHub 更新 Trending 页面 HTML 结构后，`TrendingParser` 可能无法正确提取字段，导致返回空列表或字段缺失。

**防护**：
- 解析器使用多重定位策略（class 名 + tag 层级 + href 模式），对小幅结构变化有一定容错
- star/fork 计数有备用推断逻辑（"第一个 muted link 是 stars，第二个是 forks"）
- stars 增长文本用正则兜底（`(\d[\d,]*)\s+stars\s+(today|this week|this month)`）
- HTML 解析结果为空时自动降级 mshibanami/GitHubTrendingRSS 后备源，输出标注实际数据源

**残留风险**：后备源不含 star/语言数据（显示 "—"）；两渠道同时失效时输出诊断提示，需人工排查。

## 风险 3：中文关键词翻译质量影响搜索

**风险等级**：低

**表现**：用户中文查询的英文翻译不准确，导致英文搜索结果偏题。

**防护**：
- 翻译由智能体完成（非脚本内置字典），能根据上下文给出准确翻译
- SKILL.md 中明确要求智能体主动提供英文翻译

**残留风险**：翻译偏差会导致部分英文结果不相关，但中文结果不受影响。

## 风险 4：评分算法偏向高 star 项目

**风险等级**：低

**表现**：`log10(stars) × 10` 权重较高，可能导致小众但精准匹配的项目被高 star 项目压过。

**防护**：
- match_bonus 在名称/描述/topic 命中时加分，部分抵消 star 权重
- archive_penalty 惩罚归档项目，避免推荐已停止维护的高 star 项目
- recency_bonus 奖励近期活跃项目，避免推荐古老的高 star 项目

**残留风险**：评分公式是启发式的，无法保证绝对最优排序。用户可根据表格中的 star/更新时间自行判断。

## 风险 5：描述过长被截断

**风险等级**：低

**表现**：Markdown 表格中描述超过 80 字符被截断（搜索）或 70 字符（热榜），用 `…` 标记。

**防护**：
- 截断长度合理，保留核心信息
- JSON 输出模式包含完整描述
- 项目名是可点击链接，用户可查看完整描述

**残留风险**：截断点可能在关键信息处，但 `…` 标记提示用户有更多内容。
